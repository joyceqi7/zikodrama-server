# Mini 接口职责拆分

## 版本边界与约束

Mini 的旧版基线为 `bc209b5df4b53412d47efde5e20d22afe29ca3ce`，此提交之后的功能均纳入本次调用链检查。旧版实际请求的路径、输入要求、响应字段和业务规则继续保留。服务端通过新增接口启用新版起播流程，沿用 `/api/v1/*`、`/api/v1/open/*` 分层及现有认证。

旧版基线已包含 bootstrap、公开目录及首页、个人目录、播放决策及批量决策、入剧状态、通用展示确认与查询、奖励结算、VIP 领取、解锁记录和 metrics。因此不能仅凭接口名称将广告确认或奖励接口视为可删除的新功能。

`/me/ad-experience` 是基线之后的聚合查询。新版 Mini 不再调用它或回退到 `/bootstrap`；服务端保留实现，供已经发布的中间版本兼容使用。

## 新增接口

以下均使用现有 Envelope，成功响应含 `serverTime`。个人接口使用现有 Bearer VisitorToken；错误沿用统一目录。所有标识符使用字符串。

| 方法及路径 | 输入 | 返回 | 职责边界 |
| --- | --- | --- | --- |
| `POST /api/v1/session` | `tiktokAppId`、官方 `loginCode`、可选旧 `visitorToken`、`launchQuery` | `applicationId`、`tiktokAppId`、`visitorId`、`visitorToken`、`identityState`、可选 `tiktokOpenId`、`campaign` | 登录及可信归因绑定；不查询 VIP、广告入口、播放器配置，也不生成落地响应；可信归因仍校验投放及目标可见性 |
| `GET /api/v1/open/app-config` | `tiktokAppId` | 应用身份、名称、图标、合规地址、插屏位、公开 `monetization`、`playbackSdk` | 无身份应用配置；不创建用户，不签发 Token，不返回私人权益或完整广告位清单 |
| `POST /api/v1/launch/resolve` | `launchQuery` | `launchTarget` 或 null | 只解析可见落地内容；当前会话中的可信投放目标优先，客户端参数不覆盖归因 |
| `POST /api/v1/play/entry` | `source: "launch"` 和 `launchQuery`，或 `source: "selection"`、`dramaId` 和 `episodeId` | `entry` 含 `target`、剧目和剧集摘要、`entryAdStatus`、`vipState` 与可选 `play` | 投放采用可信会话的目标，自然点选采用用户当前所选分集。两种入口共用权威线上目录和权益判定。失效投放目标返回 `entry: null`，失效点选返回 404；需前置广告时可暂不签发 `play` |
| `GET /api/v1/me/vip` | 无业务参数 | `active`、`adCount`、`requiredCount`、`progressDate`、适用时 `validUntil` | 只读个人进度和实际权益，不生成广告入口，不自动领取 VIP |
| `GET /api/v1/me/vip/offer` | 无业务参数 | `{offer: ...}` 或 `{offer: null}` | 观看时获取单个允许使用的广告入口；入口依赖失败不影响独立状态查询 |
| `POST /api/v1/me/entry-ad/shows` | `eventId`、`adUnitId`、`dramaId`，可选 `scene`（仅 entry_reward）、`episodeId`、旧 `occurredAt` | `accepted`、`entryAdStatus` | 幂等保存入剧展示并返回最新服务端进度；旧 `occurredAt` 仅解析兼容，归日仍按服务器接收时间 |

公开配置不包含 TikTok secret、BytePlus 长期凭据、播放 Token 或长期媒体地址。会话、个人状态、落地与确认响应禁止缓存；应用配置也暂用 no-store，避免旧部署缓存不一致。

## 新版 Mini 调用流程

1. 公开首页继续独立加载，SDK 尚未就绪也能展示目录。
2. 应用配置与 TikTok 登录并行。身份独立安装，不等待广告或配置；配置失败不能抹掉成功登录，重试只补尚未完成的依赖。
3. 首页在后台获取 VIP 状态。投放和自然进入目标集时使用同一个 `/play/entry`，同时取得可信目标、首屏信息、广告门禁、VIP 和当前播放决策。完整选集目录随后加载，前后台或主体切换后重新确认会失效的授权。
4. 首页 VIP 入口依据已确认的应用策略展示，不要求预先生成 Offer。需要观看时再获取 VIP Offer；显式播放决策已经提供的 Offer 可以复用。
5. 回前台、VIP 截止及手动刷新使用 `/me/vip`，不请求聚合接口。取消只读请求不影响广告原幂等键和待确认队列。
6. 只有明确的 `401/unauthorized` 触发独立 `/session` 恢复；同代并发请求共用一次恢复。普通超时、503、404不重新登录，metrics不触发身份恢复。
7. 入剧展示确认返回的进度用于展示计数模式；提前关闭也可直接更新进度。完整观看模式仍以 reward-grants 事实为准，展示回包不能覆盖完播进度。
8. 广告结算继续一次请求完成：事实与权益在既有事务中写入，响应直接返回入剧进度、VIP 状态或剧集权益，不强制再 GET。播放授权及下一条广告建议保持可选，不能推翻结算结果。

状态/确认响应缺少可用进度（例如状态补充依赖失败）时，客户端只定向恢复相应状态。已确认事实不创建新幂等键、不重复发奖；展示确认后的状态补充失败不把 accepted 改成失败。

可信投放归因仍在认证过程中解析并绑定到凭据：带有效 campaign 参数时会校验投放与目标可见性，数据库故障仍拒绝该次认证，避免丢失或伪造归因。独立落地接口负责返回页面目标，不承担重写归因或签发新凭据。

每次页面启动和显式完整重试读取应用配置；会话续签只更新身份，不热切换播放器。官方/直连播放器均由应用配置选择，基础版仍禁止高级媒体预加载。

## 基线之后功能逐项归属

| Mini 提交或功能 | 本轮处理 |
| --- | --- |
| `97fe41a` 官方回传上下文、脱敏诊断 | OpenID 从独立 session 安装；应用名称从公开配置安装。三个官方事件仍通过 SDK 直接回传，metrics只记录我方事实和回传结果 |
| `8c0af01` 超时、跨账号补领 | 新会话安装沿用主体分区、代际保护和原 ClaimID；401 不重新加载全部业务 |
| `229c32e` 广告请求、展示、失败及耗时指标 | 继续使用已有单一职责 metrics 接口；不进入结算或状态查询，不等同官方计费曝光 |
| `6d93181` SDK 直接展示广告 | 保留创建、订阅、show 的官方流程，未新增 load 或批量预加载 |
| `daf7321` 前后台及迟到补领回归 | 回归夹具迁至新接口，覆盖同一原生实例、迟到完播及两种计数模式 |
| `921fc07` 全屏广告共享退避 | 保持跨类型、广告位的互斥与退避，不因查询 Offer 创建第二个广告 |
| `9f7a0e9` 专用诊断包 | 与生产启动及结算隔离；本轮不上传/开启诊断包 |
| `d6961b7` 服务端时间 | 新接口继续使用 serverTime + 单调时钟；后台失效后查询确认，不用手机日期累计或判断权益 |
| `e586603` 最新结算状态 | 保留直接返回入剧、VIP、剧集权益；新增展示确认回包补齐展示计数路径 |
| `ea6fb74` ad-experience、前后台超时 | 新版彻底改为独立 VIP 状态/Offer；前台计时预算、取消处理保留，不再404回退bootstrap |

目录、播放决策、奖励事务、手动 VIP 领取和埋点本身具有独立业务语义，复用现有接口，不为减少函数行数拆成多次客户端写操作。

## 验证与部署

- 服务端覆盖：登录与策略故障隔离、配置与个人状态隔离、VIP 状态与入口隔离、认证要求、新旧展示入口同键幂等、服务器时间归日、旧响应保持。
- Mini 覆盖：新版实际路径、公开配置无 Authorization、按需 Offer、配置失败保留身份、并发401单次认证、取消/迟到响应、跨账号恢复、入剧展示返回状态、官方和直连页面流程。
- 保留旧版的启动、落地、入剧广告、奖励及播放合同。旧版锁定集的播放解析复用一次策略读取，批量播放解析复用同一权威线上目录。
- 无 Schema、SQL、Admin 变更。先完整部署 Server，再发布新版 Mini。旧 Mini 可继续访问新 Server；新版 Mini 要求这些新入口，不兼容缺少新入口的旧 Server，也不静默退回旧聚合流程。
- 本轮自动验证不调用真实 TikTok/BytePlus；真机上传、广告填充及平台外部网络仍需部署后验收。

本轮本地验证结果：Server `make verify` 通过；Mini `make verify` 通过（582 个 Vitest 用例、33 个 Node 用例、TypeScript 检查、Web 构建）。平台真机验收尚未进行。
