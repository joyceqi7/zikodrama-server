# VePlayer 与渠道独立发布上线手册

本分支由用户授权接入 byteplus_web。新版 Mini 上线后，应用可以按播放配置修订切换 provider；官方播放继续使用 TikTok Minis SDK，直连播放使用 BytePlus SDK、VID 与短时授权。License 随 Mini 包提供。

## 内容与发布

- 短剧管理是公共内容入口，保存资料或媒资仍形成草稿，不生成发布版本。界面不再显示内容 ready 状态或“确认就绪”；历史字段和 ready 接口保留兼容，不迁移草稿状态。
- 直连发布菜单收回短剧管理，提供“上线”“发布更新”“下线”“重新上线 Vn”及批量上线。首次上线与发布更新在事务内校验已保存资料、封面和全部分集视频，失败不改变当前版本。重新上线恢复下线前的版本，不要求新草稿完整；批量上线发布当前保存内容，各剧独立提交，成功项保留，失败项可单独重试。
- 官方发布菜单保留。草稿可独立同步 TikTok，不要求直连上线。上传视频进入 BytePlus VOD；官方同步时登记新 VID、查询就绪，再创建/更新 Album；“生成多清晰度视频（转码）”为可选项，默认不勾选。旧客户端同步空对象仍沿用原转码策略，既有工作流不被改写。
- TikTok 同步、送审、版本选择、上下架与授权在当前请求内完成平台调用；只有真实媒体处理和审核结论保留后台查询。同步后停在待送审，审核通过后由运营选择新版上线。旧线上 V1 可在 V2 同步、审核期间独立上下架，不能从最新任务推测其线上状态。
- 官方及直连分别冻结自己的内容快照和版本。编辑、同步、审核和单个渠道发布均不改变另一渠道线上内容；连载增加剧集也分别发布。
- 两渠道下线都检查各自轮播与热播引用，存在引用时用友好提示引导先移除，不展示常驻错误条。分类、轮播、热播仍由各渠道菜单维护。
- 已生成版本及官方冻结记录保护源视频、封面和分集身份。已有线上引用或活动任务时禁止删除，删除按钮与服务端同时校验。

## 数据库升级

新库执行 sql/init.sql 和全部增量；旧库仅执行尚未应用的增量。基线和已发布增量保持不变。

1. 20261009_001_direct_playback.sql：旧直连存储与应用播放模式。
2. 20261009_002_direct_menus.sql：官方与直连菜单、精确权限。
3. 20261010_001_remove_application_playback_profile_key.sql：删除应用级配置引用；当前 Token 有效期使用下文的 YAML 配置。
4. 20261010_002_content_versions.sql：前轮已发布的开发期共享版本结构增量，保持原样。
5. 20261010_003_channel_publication_versions.sql：移除共享内容版本表，创建直连自己的版本表，清除未上线直连的开发期发布指针和操作；不改变已有 TK 内容、任务或编辑状态。

6. 20261011_001_simplify_direct_operations.sql：合并直连记录菜单的已有显式菜单授权，移除记录菜单和首页复制操作；保留自定义子节点及业务配置，不授予新操作权限。已有测试库也须单独执行此菜单增量。
7. 20261011_002_remove_official_review_menu.sql：移除独立官方审核菜单，历史收回发布详情；删除旧菜单授权，不自动授予官方发布菜单。自定义子树原地保留目录容器和启停状态。
8. 20261011_003_merge_direct_publication_menu.sql：合并直连发布菜单至短剧管理，保留操作节点主键及角色关联；旧祖先停用时保持操作不可用。仅同时拥有内容读取权限的旧菜单使用者获得短剧菜单入口，不新增业务权限。

本轮已删除 VePlayer 新表的测试库直接执行 sql/feat_veplayer_tables.sql，不能叠加上述结构增量；菜单与角色关系保留。

直连版本只从首次直连上架生成 V1；TK 使用已有官方版本和任务快照；已有 TK 线上内容、授权、官方 Album/Review 身份与任务不变。审核驳回后的重送同时检查冻结内容，不能用相同内容的新版本绕过修改要求。

升级前停止旧 API 和全部 Worker，备份并记录线上快照、配置、角色与权益数量。执行增量后配套部署新版 Server 与 Admin，旧版 Server 不得混跑；已有 Mini 继续消费原 TK 合同，支持直连的 Mini 读取当前直连上架内容，不要求理解管理端发布版本。当前 Schema 为 144 张表、92 个默认系统权限节点（自定义容器另计），无外键及 CHECK。应用启动不自动迁移；本轮没有在业务数据库执行 SQL。

内容编辑使用 content.drama.update；直连单条、批量上线和恢复原版本要求 operations.direct_publication.read/publish，下线要求 read/offline，编辑权限不等于发布权限。TK 同步、审核、上线与授权继续使用各自精确权限。菜单迁移须配套 Server 与 Admin 发布，应用启动不自动执行 SQL。

## 配置

服务端始终装配直连播放能力。应用模式及 playbackRevision 由服务端可信配置决定，客户端不自主切换 provider。

```yaml
business:
  direct_playback_token_ttl_seconds: 300
```

每个实例运行媒体、官方发布和指标职责；媒体与官方发布任务通过 MySQL 租约协调领取。直连上下架使用同步事务。上线前升级全部实例及清理任务，避免旧程序遗漏新内容引用。

所有直连应用使用当前 YAML 的 `business.direct_playback_token_ttl_seconds`，所有实例必须配置 60～900 秒，示例为 300 秒；缺失或越界拒绝启动，修改后重启全部实例。签名及响应 `expiresAt` 使用同一有效期。原 `global_configs.playback.default` 不再参与运行，可以从后台普通配置列表删除，无需结构迁移。

License 位于 Mini 的 src/assets/veplayer 随包提供，SDK AppID 与 License 一起维护；服务端 bootstrap 不再返回 appId。须同步升级 Mini，不能让仍要求该字段的旧直连包连接新服务端。许可须覆盖页面实际顶层域名。播放地址及原片编码在 BytePlus 控制台维护。

修改应用 provider 由 applications.update 应用编辑权限控制，并传当前 playbackRevision。修改保留应用身份、广告位、变现策略和权益。直连应用自动消费所属主体的直连上架内容；TK 应用仍须官方授权。两个渠道首页配置按主体独立保存，各自维护分类、轮播和热播，不提供跨渠道复制入口。

## 同主体应用官方内容预授权

官方发布详情的「管理授权」允许选择同一主体内已启用且已配置 Client Key 的应用，包括当前使用独立播放器的应用。授权成功仅登记官方内容授权，不切换播放器，也不把官方内容加入直连目录。应用切到官方播放器后，复用已有有效授权；切回独立播放器不自动撤销授权，撤权仍由运营显式操作。

候选由安全应用选项提供播放通道与 Client Key 已配置状态，不依赖应用资料读取权限；实际授权仍要求 `content.drama.distribute` 并经服务端校验主体、内容状态、应用状态和平台结果。拥有方无需重复授权，新建应用不会自动授权，平台调用失败不会展示为已授权。
