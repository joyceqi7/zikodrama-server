# 单语言与无字幕版本部署

2026-09-12 版本要求 Schema `2026-09-12-v21`。消费者界面固定英语，管理端固定中文；内容保留主标题、主简介和单份 VIP 文案，不使用历史翻译覆盖主字段。原始音频语言继续用于官方内容发布。

## 数据库

本项目仍按上线前的最终 Schema 管理，不提供运行时迁移。新环境先向空数据库执行 `sql/init.sql`，再启动当前服务和更新两个前端。已有数据库需要先独立完成结构变更；服务不维护结构版本表，也不自动升级数据库。

本次移除四张翻译表：`drama_translations`、`episode_translations`、`tiktok_tag_translations`、`application_monetization_config_translations`；同时移除应用的 `default_locale` / `supported_locales_json`、分集的四个 `subtitle_*` 状态字段及发布任务的 `subtitle_bindings_json`。主内容、原音语言、媒资、平台映射、广告规则与权益表保留。

需要保留旧库数据时，应先停服和备份，再在独立 v21 数据库导入保留字段并验证。正在 `prepare_subtitles` 阶段的旧发布任务需要在核对 Album 和版本状态后离线处理，不能直接交给新 Worker，也不能无条件重新发起平台发布。旧版和新版实例不能混用同一数据库。回退需要同步恢复旧二进制、前端和旧库备份。

此次开发验证仅初始化隔离测试数据库，没有修改已有业务库。历史字幕媒资不会被批量删除；旧媒资引用类型仅保留在通用引用释放与清理流程中，防止正常内容删除产生遗留引用。

## 验收

- 管理端不再提供通用语言配置和字幕入口。2026-09-15 起，TikTok 标签独立菜单允许维护英文展示名，官方目录仍不可编辑；见 [运营 API](operations-api.md#内容目录管理)。
- API 不返回通用翻译映射或应用语言列表；旧字幕路由返回 404。标签更新路由只接受 `englishName`，不恢复旧多语言合同。
- 发布流程经过视频登记、转码、Album 更新、审核、上线与应用授权，不再等待或登记字幕。
- 消费者固定英语，官方播放器禁用自动字幕与字幕插件；已烧录进视频画面的文字不受影响。
- 执行三仓库 verify 和隔离 MySQL 集成测试；正式发布前在 TikTok 真机检查播放器、切集、登录和广告权益。
