# Redis 存储边界检查（2026-09-17）

## 约束与检查范围

MySQL 保存全部业务权威数据。Redis 仅保存可以丢弃和重新计算的缓存，不能保存唯一业务事实；配置保存以 MySQL 提交为准。检查范围包括 server 的运行时装配、Redis 适配器、消费者和运营入口，以及 mini/admin/nginx 的 Redis 引用。未读取或修改参考项目。

## 盘点与处理

| 用途 | 权威来源 | Redis 角色与处理 |
| --- | --- | --- |
| 全局轮播、人工热播 | 新表 `homepage_recommendations` | 已移除 Redis 持久化仓储；管理读写走 MySQL，C 端缓存完整展示结果 |
| 分类排行榜 | `category_rankings` | 不以 Redis 保存成员、顺序或显隐 |
| 媒资、拥有方、广告等全局配置 | `global_configs` | 当前直接读 MySQL 主节点；不使用 Redis 配置缓存 |
| 公开目录、分页、详情、推荐摘要 | MySQL 线上内容、授权及推荐配置 | 有限 TTL 的可重建结果；按应用和查询隔离，错误不缓存 |
| `drama:{consumer-catalog}:version` | 无业务数据 | 可丢弃的随机缓存失效标记；虽然无 TTL，但不承载修订、配置或业务事实，丢失后可生成 |
| 消费者 UID 发号进度 | `id_allocators.consumer_domain` 的永久预留水位与 MySQL 用户表 | 共享当前段、备用段、游标与预取租约；丢失后舍弃未使用号段并从 MySQL 重新预留，不能恢复旧游标继续发号 |
| 管理身份、权限、消费者身份、权益、奖励、任务、统计 | MySQL 对应业务表；消费者凭据自包含 | 未发现运行时 Redis 权威写入 |
| 请求限流 | 有界进程内计数 | 不使用 Redis，不承担持久化事实 |
| mini/admin/nginx | HTTP API、客户端本地展示状态 | 无直接 Redis 业务连接；测试异常字符串不构成存储使用 |

## 一致性和故障处理

轮播与热播按栏目唯一键串行化首次创建和事务内整体替换，修订冲突返回既有 409 合同。管理端读主节点，避免缓存或副本延迟带回旧版本。保存成功后失效所有应用结果缓存，防止失效前的查询重新填入旧数据；失效失败保留成功结果并记录错误，由有限 TTL 兜底。

内容缓存启动初始化失败时记录实际错误，当前进程禁用缓存而继续读写 MySQL；恢复缓存需要重启该进程。运行中 Redis 断连时内容读请求回源，保存不因失效失败而丢失提交。就绪检查仅以 MySQL 为准。MySQL 失败仍返回错误，不伪造成功或空配置。

UID 共享进度是可丢弃缓存，但不能从 MySQL 重建原段的精确游标；重建方式是永久舍弃旧段、预留新段。新用户发号依赖 Redis，故障时返回失败，不降级为本地发号；已有用户登录不依赖该进度。Redis 连接启动初始化失败后，需要重启应用重新初始化客户端；运行期间的短暂断连由客户端恢复。Redis 异步复制或持久化可能回滚已经消费的游标，恢复时必须先阻断发号、停止旧实例及旧主写入、清除对应 UID 缓存，之后才开放发号。正常应用发布不得清理缓存。完整流程见 [UID 分配与恢复](uid-allocation.md)。
